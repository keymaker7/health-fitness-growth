# Microsoft 에이전트 · 워크플로 설계

건강체력 성장일지에 붙이는 Copilot Studio 에이전트와 워크플로의 전체 구조입니다. Microsoft 제품만 사용합니다.

## 전제

- 앱의 학생 기록은 **브라우저 IndexedDB**에만 저장됩니다. 에이전트와 흐름은 앱을 직접 읽지 못합니다.
- 다리는 앱의 **전체 백업 JSON**입니다. CSV는 사람이 Excel로 볼 때만 쓰고, 흐름이 먹는 것은 JSON입니다.
- 학급 데이터는 **SharePoint 리스트**에 쌓습니다. 학생은 **번호 또는 닉네임**으로만 표기합니다.
- 모든 에이전트는 학교 Entra ID 테넌트 안에서만 게시하고, 공유 파일에는 Purview 민감도 레이블을 겁니다.

## 전체 그림

```
[교사] ──▶ 체육 운영 도우미 (부모 · Teams 교사 팀)
              │
              ├─ 자식 에이전트 ─ 측정 안내
              ├─ 자식 에이전트 ─ 처방 해설
              ├─ 자식 에이전트 ─ 학급 현황 ──▶ 에이전트 플로우 F1
              │
              ├─ 연결 에이전트 ─ 건강체력교실 운영 ──▶ F3
              └─ 연결 에이전트 ─ 가정통신문 작성 ──▶ F4

[학생] ──▶ 성장 코치 (독립 게시 · Teams 학생 팀, 부모에 연결하지 않음)

[배경]  Power Automate  P1 취합 · P2 주간 카드 · P3 참여 알림 · P4 갱신 알림
                              │
                              ▼
                    SharePoint 리스트 (학생 / 운동기록 / PAPS측정)
```

## 자식이냐 연결이냐

| 구분 | 성격 | 여기서 맡는 것 |
| --- | --- | --- |
| 자식 에이전트 | 부모 안의 가벼운 묶음. 별도 게시 없음. 부모와 같은 권한 | 측정 안내, 처방 해설, 학급 현황 |
| 연결 에이전트 | 독립 게시된 별도 에이전트. 자체 지식과 권한 | 건강체력교실 운영, 가정통신문 작성 |

지식과 도구를 논리적으로 묶는 수준이면 자식으로 충분합니다. 권한이 다르거나(파일 생성, 메일 초안) 다른 에이전트에서도 재사용할 것이면 연결로 뺍니다.

**학생용 성장 코치는 부모에 연결하지 않습니다.** 연결 에이전트는 부모가 갖지 못한 권한을 대신 행사할 수 있어, 교사용 부모에 학생용을 매달면 경계가 무너집니다. 완전히 별도로 게시합니다.

## 에이전트

### 부모 — 체육 운영 도우미

Teams 교사 팀에 게시. 스스로 답하지 않고 어디로 보낼지만 정합니다.
지침에 각 자식·연결 에이전트를 언제 부르는지 명확히 적습니다. 라우팅 품질은 이 설명문에서 결정됩니다.

### 자식 1 — 측정 안내

- 지식: SharePoint `체육/PAPS 운영` 라이브러리 ([설계서](./paps-guide.md))
- 다루는 것: 13개 종목 측정 방법, 준비물, 안전 수칙, 파울 규정
- 학생 이름이나 개별 측정값이 들어오면 대화 종료

### 자식 2 — 처방 해설

- 지식: `src/lib/prescription.ts`의 FITT 표와 점증 규칙을 옮긴 문서, [진행 계획](../plan.md)의 근거 표
- 도구: 에이전트 플로우 F2
- 답하는 질문: "왜 이 아이는 주 3회인가", "왜 최고 기록이 아니라 최근 평균으로 목표를 잡나"
- 개별 학생이 아니라 **규칙**만 설명합니다. 학부모 상담과 관리자 질의 대응용

### 자식 3 — 학급 현황

- 도구: 에이전트 플로우 F1
- 반환: 참여율, 요인별 분포, 지난주 대비 변화
- 개별 학생 조회 요청은 거절

### 연결 1 — 건강체력교실 운영

- 지식: 교육청 기본 계획, 학교 운영 계획, 서식
- 도구: F3
- 산출: 계획서 초안, 주차별 운영안, 결과 보고서 초안

### 연결 2 — 가정통신문 작성

- 도구: F4
- 산출: Word 초안과 Outlook 메일 초안. 발송은 사람이 누릅니다

### 독립 — 성장 코치 (학생용)

가장 마지막에 만듭니다. 금지선: 친구와 비교, 체중·식단·의료 조언, 개별 진단.
통증을 말하면 교사에게 알리라고 안내하고 대화를 정리합니다.

## 워크플로를 어디에 둘지

같은 엔진이지만 성격이 다릅니다.

| | 에이전트 플로우 | Power Automate 클라우드 흐름 |
| --- | --- | --- |
| 부르는 주체 | 대화 중 에이전트 | 예약, 파일 생성 같은 시스템 이벤트 |
| 실행 권한 | **대화한 사용자 권한** | 연결 소유자(서비스 계정) 권한 |
| 과금 | Copilot 크레딧 | Power Automate 라이선스 |
| 제약 | 에이전트 호출 시 2분 제한 | 예약·트리거가 기본 |

실행 권한 차이가 설계상 가장 중요합니다. 에이전트 플로우는 말을 건 교사의 권한으로 돌기 때문에, SharePoint 리스트 권한을 담임으로 제한해 두면 **에이전트 지침이 뚫려도 남의 반 데이터를 못 가져옵니다.** 방어선을 프롬프트가 아니라 권한에 두는 방식입니다.

반대로 배경 흐름은 넓은 권한으로 돌므로 결과를 채널에 뿌리지 말고 담임 개인 메시지로만 보냅니다.

## 에이전트 플로우 (대화 중 호출)

| 번호 | 이름 | 입력 | 출력 |
| --- | --- | --- | --- |
| F1 | 학급요약조회 | 학년, 반, 기간(일) | 참여 학생 수, 평균 기록 수, 요인별 분포 |
| F2 | 처방근거조회 | 체력요인 | FITT 값(주당 횟수, 1회 분, 점증 규칙)과 출처 |
| F3 | 교실서류초안 | 학기, 대상 인원, 종목 | Word 초안 링크 |
| F4 | 통신문초안 | 학급, 기간 | Word 초안과 Outlook 초안 링크 |

F1은 집계값만 반환하게 흐름 자체에서 막습니다. 개별 행을 절대 내보내지 않으면 프롬프트로 유도해도 새어 나갈 것이 없습니다.
F2가 있는 이유는 환각 방지입니다. 숫자는 생성하지 말고 흐름이 돌려준 값만 말하도록 지침에 못 박습니다.
F3과 F4는 사람 확인 액션을 넣어 승인 뒤에 파일을 만듭니다.

## Power Automate 클라우드 흐름 (배경)

| 번호 | 이름 | 트리거 | 하는 일 |
| --- | --- | --- | --- |
| P1 | 기록 취합 | `기록업로드` 라이브러리에 파일 생성 | 백업 JSON 파싱 → 리스트에 행 추가(중복 제거) |
| P2 | 주간 성장 카드 | 매주 금요일 | 학급 집계를 Teams 채널에 카드로 게시 |
| P3 | 참여 저조 알림 | 매주 월요일 | 2주간 기록 0인 학생을 담임에게 개인 메시지 |
| P4 | 갱신·재측정 알림 | 매월 1일 | 재측정 달이면 Planner 작업 생성 |

P1이 나머지 전부의 기반입니다. 여기부터 만들고 실제 백업 파일로 검증한 뒤 다음으로 갑니다.

## SharePoint 리스트

**학생** `번호`(제목) · `닉네임` · `학년` · `반` · `담임`(사용자) · `활성`

담임을 사용자 열로 두면 P3에서 수신자를 바로 꺼낼 수 있습니다.

**운동기록** `키`(제목) · `번호` · `날짜` · `시각` · `종목` · `체력요인` · `횟수` · `시간분` · `정확도` · `운동후기분` · `기록방법`

**PAPS측정** `키`(제목) · `번호` · `날짜` · `종목` · `체력요인` · `측정값` · `단위` · `등급`

키는 `번호_날짜_시각_종목`입니다. 같은 파일을 두 번 올려도 중복이 쌓이지 않습니다.

## 앱이 내보내는 JSON

`설정 → 전체 백업 저장`으로 받은 파일을 그대로 올립니다.

```json
{
  "app": "health-fitness-growth",
  "exportedAt": "2026-08-18T...",
  "stores": {
    "users": [{ "displayName": "5-3-12", "grade": 5, "className": "3반" }],
    "sessions": [{ "exerciseName": "줄넘기", "startTime": "...", "durationSec": 240,
                   "count": 118, "accuracy": 0, "afterEmotion": "proud", "source": "camera" }],
    "paps": [{ "eventId": "pacer", "measuredAt": "...", "value": 42, "unit": "회", "grade": 4 }]
  }
}
```

앱 설정의 이름 칸에 `5-3-12`나 닉네임을 넣으면 그대로 실려 나갑니다. 실명을 넣지 않습니다.

## 만드는 순서

1. SharePoint 리스트 세 개
2. P1 기록 취합 — 백업 파일 하나로 검증
3. 측정 안내 자식 + 부모 에이전트 (게시)
4. F1 + 학급 현황 자식
5. P2 주간 카드
6. F2 + 처방 해설 자식
7. 연결 에이전트 둘, F3·F4
8. P3, P4
9. 성장 코치 (학생용)

3번까지 되면 교사가 실제로 쓰기 시작할 수 있습니다.

## 점검

- [ ] 부모가 질문마다 올바른 자식·연결로 보내는지 활동 추적기로 확인
- [ ] F1이 개별 학생 행을 반환하지 않는지 확인
- [ ] 다른 반 담임 계정으로 F1을 불러 남의 반이 안 나오는지 확인
- [ ] 배경 흐름 결과가 채널이 아니라 개인 메시지로 가는지 확인
- [ ] 학생 이름 + 숫자를 입력했을 때 모든 에이전트가 차단하는지 확인
- [ ] 성장 코치가 교사용 부모에 연결되어 있지 않은지 확인
